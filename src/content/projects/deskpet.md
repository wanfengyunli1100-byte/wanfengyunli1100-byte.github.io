## 一句话说清

一块方形的白色小盒子，1.3 寸 OLED 显示时间、温湿度和像素表情，摸头会开心、不管它会睡着。
**软件已经全部跑通并烧录验证；硬件死在"第一次上电"这一步。** 现在在做第二版 ——
不是修修补补，而是把电路和结构重做一遍。

## 问题：软件全通，硬件在上电那一刻失败

固件侧按计划收尾：分层重构完成、低功耗 STOP 休眠与触摸唤醒实测通过、
量产自检（长按摸头 3 秒逐项检测 OLED / DHT11 / DS3231 / 蜂鸣器 / 触摸）就位，
PC 端单元测试 `ALL TESTS PASSED`，多次烧录验证行为一致。

然后是 PCB：打样、焊接、上电 —— **三个症状同时出现**：

| 症状 | 现象 |
|---|---|
| 1 | 蜂鸣器**长鸣**不止（预期只在情绪触发时短促响） |
| 2 | **自锁开关断开后，屏幕与电路仍在供电** |
| 3 | 开关开久后出现**烧焦味** |

外加一个机械问题：部分焊孔与模块排针**错位**。

**排查方向与根因假设**（三条都指向电源链，而不是某个模块）：

1. **开关没有串在总回路上** —— 它可能只切断了某一路（例如升压模块的输入），
   而电池到负载之间存在第二条通路，于是"关机"关不干净；
2. **蜂鸣器 I/O 未真正落到 MCU 引脚** —— 或模块接错，导致它一直处于导通状态；
3. **电源区域短路 / 过流** —— 烧焦味最可能的来源，需断电单独查充电模块、升压模块与电池线。

教训很直接：**这三条都不是"代码 bug"，而是"设计缺陷"** —— 画板子时没人在图上拦住它，
等到焊接上电，代价就是整板重来。

## 方案演进的取舍：从裸芯片到模块底板

第一版方案走的是**裸芯片集成**：STM32F103C8 裸片直接贴板，配合 0603 封装的阻容。
理论上最紧凑，实际遇到了两堵墙 —— 手工焊接难度过高（0603 小件 + 多模块），
以及一处接线错误就能让整板报废。

于是中途改成**模块底板方案**：核心板用 2×20 排母插接（Blue Pill），
OLED / 温湿度 / 时钟 / 触摸 / 蜂鸣器全部以模块形式插接，板上只留电源链与排母。
这个方案的取舍很清楚：

- **换来的**：元件数量骤降、焊接点集中在排母与电源链、模块可单独替换排错；
- **付出的**：体积变大（塞进外壳更吃力）、成本高于裸片方案、多一层接插件接触风险；
- 设计上还专门核对了 Blue Pill 的排针定义（用 Wokwi 的板级 JSON 与 bridle 绑定**双重确认**），
  生成原理图后 ERC 报 **0 错误 0 警告**，网表 19 条网络与接线表逐条核对通过。

即便这样，**上电仍然失败** —— 因为出问题的是电源链，而电源链在两次方案里都是自己画的。

## 实测：软件侧是一份可复用的硬资产

| 模块 | 做法与实测结果 |
|---|---|
| 分层架构 | `Application`（传感器 / 显示 / 自检任务）+ `Middleware`（情绪状态机）+ `Drivers/BSP`（板级驱动）+ `Core`；主循环 10ms 周期 |
| 情绪系统 | 单一 `mood` 变量（**-3 ~ 10**）驱动全部表情；`0 = 休眠黑屏`；清醒每 10s 衰减、休眠每 2min 衰减 |
| 三层表情优先级 | 温度 > 30°C 强制 HOT → 临时表情（3s）→ 休眠 → mood 常态映射（ANGRY / JUST_WOKE / IDLE / HAPPY / VERY_HAPPY） |
| 低功耗 | STOP 深度睡眠 + EXTI 触摸唤醒；进 STOP 前复位触摸状态防误唤醒；整机电流预估 **50 ~ 150 μA**（按 1000mAh 电池折算约月级续航） |
| 触摸手感 | 30ms 防抖 + 短按/长按区分；**短按松手才反馈**（刻意做出"反应慢半拍"的性格） |
| 异常处理 | 外设超时 + 连续失败降级显示（`ERR:x` / `--:--`），任何外设故障都不卡死 |
| 量产自检 | 长按摸头 3 秒进入，独占屏幕逐项检测并显示 PASS / FAIL |
| 可测试性 | 情绪系统是纯 C 逻辑（不碰硬件），WSL gcc 直接编译测试：初始化 / 摸头摸脸 / 临期过期 / 温度覆盖 / 衰减入睡 / 休眠唤醒 / 负 mood 边界 |

**这是这个项目最有价值的部分**：硬件可以重画，但"把交互逻辑写成可脱离硬件测试的纯逻辑"
这条经验，和已经验证过的固件代码一起，直接被 v2 继承。

## 复盘

1. **软硬件的验证成本不对称**：软件改一行重烧一次几秒钟，硬件错一处就是打样 + 焊接 + 上电 + 重来。
   所以硬件的"图上评审"必须比软件更严 —— 这次恰恰是 ERC 干净、网表核对通过，**却没人审电源链拓扑**。
2. **"接线错误即烧板"这件事，必须用器件兜住**：保险丝、防反接、分轨标注 —— 靠人不出错是靠不住的。
3. **手工焊接不是能力问题，是工程选择问题**：0603 + 多模块就是不适合手工；
   v2 直接走 SMT 贴片，只把排母和模块留给自己焊。
4. **外壳要趁早量尺寸**：3D 打印从零起步、元件高度没量全，导致结构反复返工。

v2 的待决策清单目前**全部开放**，这正是"先谋后动"的落地：

| # | 决策项 | 备选 |
|---|---|---|
| D1 | 主控选型 | STM32F103C8T6（有已验证固件资产）vs ESP32-S3（可复用开源生态） |
| D2 | 电源链拓扑 | 开关串总回路 + 保护器件（保险丝 / 防反接 / 分轨标注） |
| D3 | 装配方式 | 嘉立创 SMT 贴片 vs 手工焊（倾向 SMT，只留排母自焊） |
| D4 | 交互方案 | 单触摸（v1 最终砍到只剩摸头）vs 双触摸 |
| D5 | 外壳形态 | v1 参数 87×57×45，需重量元件高度与公差 |
| D6 | 电池与续航 | 规格与目标续航（v1 按 1000mAh / 休眠 150μA 估约 277 天） |

**v2 的审查重点**（写进任务板，作为打样的前置条件）：
电源链拓扑是否真的修掉了 v1 的三个症状；是否有防止接线错误即烧板的保护；
焊接难度是否真的下降。三条都过了，才允许进入原理图 → PCB → 打样。
