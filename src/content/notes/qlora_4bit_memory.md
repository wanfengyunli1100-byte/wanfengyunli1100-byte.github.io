## 结论先说

把 Qwen2.5-3B 从约 6GB 显存压到约 2.5GB，靠的不是"把模型变小"，而是**把权重从 FP16 换成 4bit**
外加**只训练一小撮低秩适配器**。前者省推理显存，后者省训练显存。

## 三段显存开销

| 阶段 | 主要占用 | 量化能否帮忙 |
|---|---|---|
| 加载权重 | 参数量 × 每参数字节数 | 能，直接按位宽线性下降 |
| 训练 | 优化器状态 + 梯度（通常是参数的数倍） | 能，冻结主权重就不产生这些 |
| 推理 | KV Cache + 激活值 | 不能，跟输出长度成正比 |

FP16 下 3B 参数约 6GB；4bit 后约 1.5–2GB，加上 KV Cache 和运行时开销，实测落在 2.5GB 附近。

## 关键取舍

**为什么用 QLoRA 而不是全量微调**：全量微调要给每个参数配梯度与优化器状态，
显存需求是参数量的数倍；QLoRA 冻结主权重，只训练低秩矩阵，适配器只有几百 MB。

**为什么 loss 收敛到 2.19 就停**：284 条数据、小模型、单轮训练，
继续压 loss 大概率是过拟合而不是学会。判断依据是留出的验证集，不是训练 loss 本身。

## 踩过的点

- **4bit 量化的加载顺序**：先按 4bit 加载再挂适配器，反过来会先撑爆显存
- **推理框架要匹配**：训练用一套、推理换另一套时，务必确认量化格式能互通
- **KV Cache 是隐形大户**：上下文长度翻倍，显存占用也跟着涨，与量化无关

## 一句话

量化买到的是"能跑起来"，适配器买到的是"能改得动"。
两件事的显存账要分开算，混在一起就会得出"4bit 应该只占 1/4 显存"这种错误预期。
